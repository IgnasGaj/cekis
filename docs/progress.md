## Sprint 1 audit correction, 2026-10-05

The [audit supplied by the owner](../sources/sprint-01-audit-and-fixes.md) identified three findings. F1 is fixed by moving the atomic PostgreSQL send quota to Better Auth's `sendMagicLink` callback, which runs after its schema, origin/CSRF and IP rate-limit checks and before SMTP delivery. Invalid and rejected requests do not use the email quota. Failed SMTP attempts do count toward the abuse limit. F2 is fixed by requiring the supported success and Lithuanian error callback paths before sending, and by sending incomplete or unsafe verification URLs to the Lithuanian invalid-link screen.

F3 is partly resolved: npm MailDev was removed in favor of the free standalone Mailpit binary (the Docker option still works), and an esbuild override replaces Drizzle Kit's vulnerable nested esbuild. This override is outside Drizzle Kit's declared esbuild range and must be revalidated when dependencies change. Clean install, repeatable fresh migrations, Drizzle generation, local SMTP, lint, types, eight unit tests, eight browser tests and production build passed on Node 22. A separate standalone Mailpit SMTP/API smoke test passed. The corrected browser tests cover untrusted Origin plus Fetch Metadata, malformed auth payloads, missing callbacks, real emailed URLs, exact concurrent quotas and Better Auth's rate-limit rejection, alongside the original auth lifecycle tests. A development-server body-read error during cold starts led to forwarding a fresh request body to Better Auth; two complete browser reruns then passed.

The first correction push failed at CI's unit-test step. Its macOS-generated lockfile lacked Linux optional native packages. A fresh cross-platform lockfile passed `npm ci` and all eight unit tests in a Node 22 Linux container, followed by local lint, types, two full browser runs, build and fresh/repeated migrations. The exact final pushed SHA and CI result are given in the correction handoff.

At that correction point, the full dependency audit was **not clean**: five high entries remained in one development-only ESLint chain, `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces@3.0.3` ([GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)). The latest published `braces` was 3.0.3 with no compatible upstream fix. `npm audit --omit=dev` reported zero findings. These packages ran in local/CI linting, not the application server; their pattern processing could be exposed to untrusted lint input. npm's suggested `eslint-config-next@14.2.35` was incompatible with the project's Next 16 lint setup, so it was not forced in. This historical finding was resolved in Sprint 01.2 below.
