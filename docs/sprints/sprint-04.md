# Sprint 4 — OCR and receipt review

A signed-in owner opens **Nuskaityti ir peržiūrėti** from an attached receipt on a purchase. The review page uses the private authenticated content endpoint for its preview and for OCR input. JPEG and PNG scanning runs only after the user asks for it. The original bytes and Sprint 3 storage state are never changed by OCR. PDF remains previewable/downloadable and has a clear manual entry path; this sprint does not scan PDF pages.

Browser OCR uses Tesseract.js **7.0.0** with locked `tesseract.js-core` **7.0.0** and pinned `@tesseract.js-data/lit` and `eng` **1.0.0** packages, using the `4.0.0_best_int` trained data. The [Tesseract.js release notes](https://github.com/naptha/tesseract.js/releases/tag/v7.0.0) confirm the browser worker API; its [local installation guide](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md) documents `workerPath`, `corePath` and `langPath`. `npm run ocr:prepare` copies the worker, all core variants and `lit`/`eng` compressed trained data into ignored `public/ocr/`. `predev`, `prebuild`, Playwright and CI prepare them reproducibly. The browser loads these assets from the same origin; scanning makes no request to a paid provider or LLM. The OCR module is loaded on demand in a separate browser worker. Cancellation sends a stop message that terminates its nested Tesseract worker, then closes the outer worker. A one-second fallback ends a broken outer worker. Unmount aborts receipt fetch and sends the same stop message. A new attempt gets a new worker.

`src/lib/ocr-parser.ts` converts only supported, well-labeled OCR text into suggestions. It recognizes common Lithuanian/English date forms, labeled totals and receipt numbers, and a single plausible priced product line. Multiple dates/products remain uncertain. Currency is suggested only for explicit EUR, USD, GBP or PLN signs/codes. The total is shown separately and never used as the purchase's product price. Suggestions do not overwrite existing purchase fields; the user can apply each value explicitly, edit it, or ignore it. No raw OCR text is stored.

Migration `0007_watery_iron_man.sql` adds nullable, constrained `receipt.receipt_number`. The review save endpoint validates all purchase fields with the existing server parser, checks authenticated ownership and the ready receipt link, and updates the existing purchase and receipt number in one transaction. Replays update the same purchase and do not create duplicates. The original receipt, its link, object key and content hash stay unchanged. A review can be completed manually after failure, cancellation or without scanning.

Warranty duration, end dates, reminders, categories, analytics, line-item splitting and PDF OCR remain outside Sprint 4. Sprint 5 is warranty tracking.
