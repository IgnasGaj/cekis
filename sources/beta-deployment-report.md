## Configuration and cost

The Render blueprint defines one Frankfurt Node web service on the Free plan. The service uses the owner's direct Neon PostgreSQL connection through a limited `cekis_app` role, a private Neon Object Storage bucket for originals, and Brevo SMTP on port 2525 with STARTTLS. Render has the 17 runtime settings required by the app and does **not** have the migration-owner URL. The ignored `.env.local` holds local credentials; Git ignores it, and no credential is in this report or the committed changes. The verified sender is configured only in the environment.

`REMINDER_TRANSPORT_ENABLED` is enabled in the live Render environment. The blueprint entry was changed from a hardcoded `false` to `sync: false` so a future blueprint sync preserves the dashboard value. The live value remained `true` after the PR #5 auto-deploy. Render's [Blueprint specification](https://render.com/docs/blueprint-spec) documents this behavior. No paid plan, trial, payment method, or Sprint 9 work was activated.

The scheduled [beta maintenance workflow](../.github/workflows/beta-maintenance.yml) is enabled with seven GitHub Actions secrets for the limited database role, private storage and protected reminder worker, plus repository variables `BETA_APP_URL` and `BETA_MAINTENANCE_ENABLED=true`. The [successful manual run](https://github.com/IgnasGaj/cekis/actions/runs/38217798669) on October 12 completed cleanup with zero candidates examined, zero deleted and zero failed; the reminder worker reported zero claimed, accepted, retried, failed, uncertain and cancelled. An earlier manual run failed at database hostname resolution before cleanup; the invalid secret values were replaced from the ignored local environment file before the successful rerun. The hourly cron was moved from minute 23 to minute 41 UTC to refresh GitHub's schedule registration after no enabled scheduled run appeared. The live reminder test below was manual.

## Operations and recovery

The service can sleep after idle time on Render Free. Free provider quotas and GitHub schedule delivery are not guarantees; see [Render Free](https://render.com/docs/free), [Neon Free](https://neon.com/blog/neon-free-plan-1-gb-per-project), and [GitHub schedule behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows).

Before a later schema change, refresh the encrypted backup and repeat its restore check. Neon's short instant-restore window is not a durable off-provider backup. Apply migrations with `MIGRATION_DATABASE_URL`, then check grants for the limited runtime role; never give the migration owner credential to Render or GitHub Actions. An application code rollback does not reverse schema migrations.
